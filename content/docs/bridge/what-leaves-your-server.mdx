---
title: What leaves your server
description: Exactly what the bridge sends to ComfiConf, when, and what it never sends.
---

ComfiConf works through the bridge's connection to the ComfiConf service, so some data has to leave your server.
The bridge also sends usage statistics to FastStats, which you can turn off. This page lists all of it.

## When the bridge connects

- A random installation id and a public key. The matching private key is generated on your server and never
  leaves it.
- The bridge version.
- The server name from `config.yml`.
- The server software and the Minecraft version.
- Once the server is paired, the names and versions of the plugins that registered settings with ComfiConf,
  and the names and descriptions of their settings pages. They are sent again when a plugin adds or removes
  settings.

## When you open the editor

- The descriptions of those settings: their labels, help texts, limits and choices.
- Their current values. Values that a plugin marks as sensitive are never sent; ComfiConf only learns whether
  such a value is set.
- The server's list of block and item names, for the material picker.

## When you apply a change

- The result, and the changed settings with shortened old and new values. ComfiConf keeps them as your server's
  change history under **Recent activity**. Sensitive values never appear there either.

## Usage statistics

The bridge also sends pseudonymous usage statistics and error reports to [FastStats](https://faststats.dev), so
ComfiConf can see how many servers run it and fix errors nobody reports. Nothing is sent during the first start of
a server, which creates the settings file, so you can turn it off before anything is sent.

- **Shortly after start, every 30 minutes and when the server stops:** a random server id created on your server,
  the bridge version, whether the bridge is connected and paired, the names of the plugins that registered settings
  with ComfiConf and the number of their settings pages, and the standard FastStats fields: Minecraft and server
  software version, online mode, player count, Java version and vendor, operating system, architecture and
  processor core count.
- **When the bridge's own code fails:** the exception type and stack trace. Exception messages are removed before
  sending, because they can contain configuration values. Errors of other plugins are not reported.
- **Turn it off:** set `enabled=false` in `plugins/faststats/config.properties` (shared by every plugin that uses
  FastStats), or `submitErrors=false` for error reports only, then restart the server.

The data reaches FastStats over HTTPS from your server's IP address.

## Never sent

<Callout tone="success" title="Not sent">
  Player data, chat, files, console output, logs, or anything a plugin does not expose.
</Callout>

- Usage statistics never include configuration values, sensitive values, the server name, player names or chat.
- It logs no configuration values, keys or pairing codes on your server, even with `debug: true`.
- It cannot read files or run commands, so it has nothing else to send.

## Your server's address

The service sees your server's IP address when the bridge connects. It is used for rate limiting and can appear
in the service's logs.

## Values you replace

A new value for a write-only secret, such as a webhook address, goes from your browser through ComfiConf to your
server when you apply it, and the plugin stores it. ComfiConf never shows it again, and it is not part of the
change history.
